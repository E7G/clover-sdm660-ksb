# Clover KS-SB Hybrid 4.19 — v0.1.0-baseline

**This release contains no tuning.** It is the A/B reference point for everything
that follows: SouthWest-NG 0.18.0 rebuilt from source, with only the changes needed
to (a) make it compile with clang-22 against its own in-tree APIs and (b) behave
identically to the firmware currently running on the device.

- Kernel: 4.19.325-cip135, `LOCALVERSION=-Clover-KS-SB-v0.1.0-baseline`
- Base: SouthWest-NG 0.18.0 (upstream `cf1462f2a`)
- Branch: `ks-sb/00-baseline`
- Boot image: stock 0.17.3 boot partition with **only the kernel region replaced**
  (ramdisk, both device trees, vbmeta and AVB footer untouched, byte-for-byte)

## What changed vs. stock SouthWest-NG 0.18.0

Build fixes (0.18.0 does not compile as-is with a current toolchain):

| File | Fix |
|---|---|
| `drivers/gpu/drm/drm_atomic.c` | `DEVFREQ_MSM_CPUBW` → `DEVFREQ_MSM_CPU_DDR_BW` (symbol renamed in-tree) |
| `drivers/gpu/drm/drm_irq.c` | `IRQF_PERF_CRITICAL` does not exist in this tree → 0 |
| `drivers/gpu/drm/msm/msm_drv.c` | `dma_set_max_seg_size()` cast, `irq_set_perf_affinity()` second argument, `strnstr()` length argument |
| `drivers/gpu/drm/vkms/` | `vm_fault_t` return type for `vkms_gem_fault` |
| `fs/notify/fanotify/fanotify.c` | missing `struct mem_cgroup *old_memcg` declaration |
| `include/linux/ramfs.h` | missing `struct fs_context` forward declaration |

Reference-parity changes (matching the 0.17.3 firmware that is running today,
verified against that kernel's `/proc/config.gz`):

| Change | Why |
|---|---|
| `CONFIG_HZ_300` | running firmware is HZ=300 (0.18.0's defconfig says 100) |
| `# CONFIG_CFI_CLANG is not set` | reference firmware has no CFI; the shadow checks are pure runtime overhead on SDA660. **ThinLTO is kept** — it is also what keeps `Image.gz` inside the 18,538,496 B kernel region of the stock boot image. |
| DroidSpaces block (`SYSVIPC`, namespaces, `DRM`, `DRM_VGEM`, `DRM_VKMS`, `SYNC_FILE`, `UDMABUF`, `DMABUF_HEAPS*`) | 0.18.0 dropped it; without it DroidSpaces and its graphics stack break |
| ReSukiSU (`CONFIG_KSU=y`, manual hook + the three auto hooks) | the running firmware is rooted with ReSukiSU; identical hook set |
| `CONFIG_LOCALVERSION="-Clover-KS-SB-v0.1.0-baseline"` | proves which kernel actually booted |

ReSukiSU is vendored as a **git submodule** (`drivers/ReSukiSU`, pinned to
`d5ba3d2d`) and exposed to kbuild through the `drivers/kernelsu` symlink, exactly
like the reference tree. The manual-hook call sites in `fs/exec.c`, `fs/open.c`,
`fs/stat.c` and `kernel/reboot.c` are the same ones the reference firmware uses.

## Not in this release (deliberately)

No CPU/GPU overclock or undervolt, no minimum-frequency pinning, no disabled deep
idle, no permanent input boost, no `performance` governor, no thermal bypass, no
5.4/5.10 subsystem ports, no BORE/Cachy/EEVDF, no schedhorizon. Phase 1 (power)
lands in v0.1.1-power.

## Install

```sh
# bootloader unlocked, device in fastboot
fastboot flash boot boot-Clover-KS-SB-v0.1.0-baseline.img
fastboot reboot
adb shell cat /proc/version    # must contain -Clover-KS-SB-v0.1.0-baseline
```

Roll back with your own boot backup, or any stock 0.17.3 boot image.

## Verify

`sha256sum` of the flashable image is in `.sha256` next to the asset. The image is
a fixed-offset splice into the stock boot image: every byte after offset
`0x11AF000` is identical to the vendor image, and the packer round-trips the
original kernel byte-for-byte (`tools/bootimg.py verify`).
