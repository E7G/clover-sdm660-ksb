# v0.1.0-baseline — Clover KS-SB Hybrid 4.19

**基线版本（Phase 0 的「零行为改动」起点）**，设备：小米平板4（clover / SDM660），系统 LineageOS 24.0（Android 17）。

- 源码树：SouthWest-NG 0.19.4（Linux 4.19.325-cip135），分支 `ks-sb/00-baseline`
- **本版本不含任何调度 / governor / 热控行为改动**（Phase 1 起才引入）；它只做三件事：
  1. 让这棵树在本机工具链下**可复现地构建出能启动的内核**；
  2. 补上 KernelSU(root) 与 DroidSpaces 容器所需的内核特性；
  3. 提供 Phase 0 的测量基础设施（boot 打包器、冷启/内存/待机脚本）。

## 构建要点（为什么必须这样配）

- 工具链：Debian clang/LLD 22.1.7，构建时显式使用 `llvm-*-22`（`/usr/bin` 下的 `llvm-nm/ar/objcopy` 是 LLVM 21.1.8，混用会让 `lib-ksyms.o` 的 `EXTERN(___ksymtab_*)` 丢失）。
- 打包：`tools/bootimg.py` 保持 header v2 的 `kernel_size` 不变（bootloader 用它计算 ramdisk 偏移），gzip 流预算 18,772,326 B；`gzip -9` 超预算时改用 **zopfli**（numiterations=15）压缩，实测 44,519,448 B → 18,305,914 B。
- **LTO / CFI / RELR 必须关闭** —— 这是本版本唯一与上游 ROM 有差异的编译配置，真机 RAM 启动 A/B 证据：

| 变体 | LTO | CFI | RELR | 真机结果 |
| --- | --- | --- | --- | --- |
| parity（上游默认） | on | on | on | 卡 Mi logo ✗ |
| relroff | on | on | **off** | 卡 Mi logo ✗（排除 RELR） |
| **safe（本版本）** | **off** | **off** | **off** | **正常启动 ✔** |

  原因：ROM 用 Android clang r596125（LLD 22.0.2，+pgo/+bolt/+lto/+mlgo）构建，该编译器已无法获取（googlesource 最高只到 clang-r584948b）；Debian LLD 22.1.7 的 LTO/CFI 产物在本机 ABL 上不启动。代价是代码体积与理论上的一点性能（Phase 0 实测未发现损失）。

## 内核新增特性（相对原厂 config，逐项均为需求驱动）

| 组 | 配置 | 原因 |
| --- | --- | --- |
| KernelSU | `KSU`、`KSU_MANUAL_HOOK`(+`AUTO_SETUID/INITRC/INPUT_HOOK`)、`KSU_MULTI_MANAGER_SUPPORT`、`DEBUG_KERNEL`、`DEBUG_FS`、`KALLSYMS_ALL` | Root（ReSukiSU `d5ba3d2d` 子模块，13 处手动 hook） |
| DroidSpaces | `SYSVIPC`+`_COMPAT`+`_SYSCTL`、`NAMESPACES`(UTS/IPC/PID/USER/NET) | 容器运行所需 |
| 图形 / DMABUF | `DRM`、`DRM_VGEM`、`DRM_VKMS`、`DMABUF_HEAPS`(+SYSTEM/DEFERRED_FREE/PAGE_POOL)、`UDMABUF`、`SYNC_FILE` | DroidSpaces 的 Wayland 宿主（anland）需要 dma-buf 与 DRM 设备节点 |
| 其它 | `LOCALVERSION="-Clover-KS-SB-v0.1.0-baseline"`、`LTO_NONE=y` | 版本标识 / 见上 |

未做（按设计文档）：CPU/GPU 超频或降压、锁 min freq、关闭深 idle、永久 input boost、performance governor、跳过热控。

## Phase 0 实测（真机 serial 2253acd9）

### 功能验证 ✔
- KSU root：`adb shell` 自动为 uid 0、SELinux 域 `u:r:ksu:s0`；kallsyms 中 `ksu_` 符号 222 个；`/data/adb/modules` 下 18 个 Magisk 格式模块正常加载（含 LSPosed `lspd`、TrickyStore）
- DMABUF/DRM：`/dev/dri/card0`、`card1`（VGEM/VKMS 虚拟设备；显示主路径仍是 FB_MSM）
- 命名空间 `cgroup ipc mnt net pid user uts` 齐全；MGLRU 启用（`/sys/kernel/mm/lru_gen/enabled=0x0001`）；`zram0` 可用；cpuidle C0–C2；PSI=1；debugfs 可用（suspend 统计可读）

### 冷启动（uid 2000 对齐，仅 COLD 样本，RUNS=12，`am start -W` TotalTime，ms）

| 应用 | stock P50/P95 | clover+模块 P50/P95 | ΔP50 | **clover 关闭模块** P50/P95 | **ΔP50** |
| --- | --- | --- | --- | --- | --- |
| com.android.settings/.Settings | 616 / 795 | 680 / 841 | +64 | **607 / 732** | **−9** |
| com.android.deskclock/.DeskClock | 599 / 673 | 671 / 698 | +72 | **602 / 659** | **+3** |
| org.lineageos.jelly/.MainActivity | 810 / 870 | 914 / 964 | +104 | **800 / 838** | **−10** |

> 三种状态都在同一台机器、同一套脚本下测量（对应 boot → 冷启 → 等 `dex2oat` 静默 → 静置 45 s → 12 轮 force-stop 后冷启，全部样本 `LaunchState=COLD`）。
> **关闭模块后冷启动与 stock 持平（settings/jelly 还略快 9–10 ms）** → +64…+104 ms 全部来自 LSPosed 对每个 app 进程的注入，**与内核无关**。

### 归因：差异来自 KSU 模块栈，不是内核 ✔
- 上表 A 中 clover 两次采样只差 ~19 MB（105 s → 464 s），说明差距**不是系统尚未稳定**造成的；
- 关闭全部 KSU 模块（无需重刷，只改 `/data/adb/modules/*/disable` 后重启）复测：可用内存只差 25 MB、匿名页只差 10 MB、zram 尺寸恢复为 stock 值、进程数 798 vs 796 —— **内核本身与 stock 基本持平**；
- 模块启用时多出的内容与 `lspd`(LSPosed 守护进程，RSS 203 MB) + `TrickyStore`(RSS 164 MB) 吻合；`pgfault` 多约 125 万次（+70%），kswapd 已开始回收（stock 为 0 次）；冷启动也同步回到 stock 水平；这些都是 **root 状态不同**造成的，与内核无关（换成 Magisk 跑同样的模块也会有同样的开销）；
- 内核自身唯一稳定的额外开销：**Slab +29 MB**（KSU / DEBUG_FS / KALLSYMS_ALL / DRM VGEM+VKMS 等结构，约 0.8% 内存）。

## 已知差异与限制
- zram 容量：模块启用时 clover 3,145,724 KB（3 GiB）vs stock 2,809,072 KB；**关闭全部模块后 clover = 2,809,604 KB，与 stock 相同** → 该差异由用户模块（`clover_pandora_compat` 等）驱动，内核未改 zram 配置。
- 90 Hz DTB（`qcom_dtb_90hz`）、SurfaceFlinger / 触控调优等由用户模块提供，与本内核无关。
- Phase 0 尚未完成：8h 熄屏待机（`tools/measure/sleep.sh`）、20–30 min 持续负载、gfxinfo 长时间采样 —— 工具已就绪，留待 Phase 1 对照使用。
- 本版本仅保证「可启动 + 功能不缺失 + 不劣于现固件」（内存/冷启动已在关闭模块的公平条件下验证持平或略优）；功耗/响应优化从 Phase 1 开始。
- 提醒：本内核内置 KernelSU，因此 `/data/adb/modules` 下的 Magisk 格式模块会自动加载（LSPosed/TrickyStore 等）。这是 root 的固有开销，与内核版本无关；如需最纯净的性能对比，请临时禁用模块后重启。
